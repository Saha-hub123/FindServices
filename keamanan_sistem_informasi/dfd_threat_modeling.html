Threat Modeling: Data Flow Diagram (DFD) & Trust Boundaries

Target Sistem: FindServices Marketplace (Laravel 12 + Vue 3/Inertia + MySQL + Reverb + Midtrans) | Metodologi: STRIDE & DREAD

Bagian 1 Pemetaan Data Flow Diagram (DFD) & 5 Trust Boundaries
Bagian 2 Keterangan Legenda Lengkap Pemetaan

1. Notasi Simbol DFD (Data Flow Diagram)

[ ]
External Entity: Entitas luar (Customer, Provider, Admin, Midtrans) sebagai sumber atau tujuan data.
( )
Process Layer: Proses / Controller logika bisnis (Laravel 12, routing, webhook handler, socket daemon).
[=]
Data Store: Tempat penyimpanan persisten (MySQL Database findservices, disk file storage, logs).
→
Data Flow (F1–F10): Aliran data terarah antar komponen lengkap dengan protokol dan muatan payload.

2. Batas Kepercayaan (Trust Boundaries)

TB-1
Zona Eksternal: Klien publik internet; semua request dianggap untrusted dan wajib diautentikasi.
TB-2
Perimeter & Ingress: Lapisan Cloudflare Tunnel & routing middleware; verifikasi CSRF token & sesi.
TB-3
Core Application: Proses bisnis internal terpercaya di host PHP 8.3 / Laravel 12.
TB-4
WebSocket Realtime: Daemon background Reverb (port 8080); membutuhkan proteksi flood & rate limit.
TB-5
Storage Layer: MySQL dan file disk; media penyimpanan data sensitif dan berkas unggahan publik.
